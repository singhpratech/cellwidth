## [0.1.0] - 2026-08-24

### Added

- `width`, `char_width`, `truncate`, `cell`, `pad_start`, `pad_end`, `center`,
  `wrap`, `graphemes`, `pieces` and `strip_ansi`.
- `Width`, a `const`-constructible measurement policy covering East Asian
  ambiguous width, tab stops, control characters, ANSI handling and whether an
  emoji ZWJ sequence counts as one glyph.
- Unicode 17.0.0 tables, generated by `tools/gen_tables.py` and committed, so
  the crate has no dependencies and no build script.
- `no_std` support. Measurement and `truncate` need no allocator; the `alloc`
  feature adds the APIs that return owned strings.

### Changed

- `wrap` now breaks at UAX #14 opportunities instead of at ASCII whitespace, so
  it finds the breaks a reader expects: between CJK ideographs, after a hyphen,
  and never inside `1,000` or between a bracket and its contents.

- `Width::DEFAULT` now treats every grapheme cluster as one glyph, rather than
  applying cluster rules to emoji but per-character rules to everything else.
  The old hybrid matched no real terminal and scored worst of the three models
  against the four that were measured. The default now reproduces kitty 0.48
  exactly, on all 32 probe cases.
- `Width::zwj_sequences` is replaced by `Width::clusters`, which subsumes it.
  `Clusters::CodePoints` (also `Width::LEGACY`) is the wcwidth-style model.

- `line_breaks`, implementing the Unicode line breaking algorithm (UAX #14).
- `Table`, a grid builder with column sizing, alignment, border styles and
  cells that wrap rather than overflow.
- `Width::of_at`, for measuring a string that starts at a known column. Width is
  not additive across a tab, so anything laying out text in pieces needs it.

### Verified

- All 766 cases of Unicode's `GraphemeBreakTest.txt`.
- All 3,944 fully-qualified sequences in `emoji-test.txt` measure two columns.
- Every one of the 1,112,064 code points diffed against glibc `wcwidth` and
  against `unicode-width`; each divergence is deliberate and pinned in a test.
- Segmentation matches `unicode-segmentation` across 9,282,875 strings.
- 33,706,777 fuzz executions across five targets with no crashes.
- 100% line and function coverage from the crate's own dependency-free suite.
- Measured against four real terminals -- kitty 0.48, WezTerm 20240203, VTE 0.76
  and Alacritty 0.17 -- by printing into a live terminal and reading the cursor
  position back. There is no probe case where every terminal disagrees with
  cellwidth. The recordings are committed in `tests/data/terminals/` and
  replayed as tests, so a change in agreement fails the build.
- All 19,338 cases of Unicode's `LineBreakTest.txt`.
- Tests run under Miri.

### Fixed before first release

Defects found by the oracles above rather than by review, each with a
regression test naming the oracle that caught it:

- Indic conjunct break rules (GB9c) were inert because a Unicode property name
  was parsed without its space.
- Nine code points were treated as zero-width although terminals draw them,
  from using `Grapheme_Extend` as a display property.
- Emoji modifier sequences on text-default emoji measured one column instead of
  two.
- `cell` returned a value narrower than requested when the input ended in an
  unterminated escape sequence, which swallowed the padding.
- A regional indicator pair carrying a combining mark measured four columns.
- `wrap` discarded a final line whose content occupied no columns.
- Trimming a dangling escape ran once instead of to a fixed point.
- Any escape ending in `m` was treated as an SGR colour code, so `wrap` injected
  resets into unstyled text.
